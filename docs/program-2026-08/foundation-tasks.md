### [ ] TASK-OSS-P0-01 — Versioned component-ownership manifest schema + Core generator/validator

_Gap: reassessment H1/H2 and P0 — the Nuxt module and resolver classify Pro components from handwritten lists, and no single deterministic authority states which exact symbol belongs to which package/subpath and whether it is a public component, compound part, composable, type, recipe, internal helper, or compatibility alias. `packages/core/manifests/public-api.manifest.json` (generated by `packages/tooling/src/manifest-generator.ts`) records Core exports but carries no ownership classification consumable by the resolver._ 🔴

```xml
<role>You are a design-system tooling engineer working in ui/dzup-ui. Follow <repo_conventions> in docs/program-2026-08/README.md §3 exactly — especially <generated_authority>: a generator reports, it never decides public API.</role>

<task>Define a versioned, deterministic component-ownership manifest schema and implement the Core generator + validator that produces it from the approved authority (package entry barrels + Contract Spec v1 metadata). The output must state, for every exported symbol, its exact package, subpath, and classification, and must surface anything it cannot classify as `unclassified` rather than guessing.</task>

<motivation>Core + Pro integration (P1), the Nuxt module, documentation generators, and release review all need one answer to "who owns `DzFoo`?". Today that answer is spread across PRO_COMPONENTS prefix lists in packages/core/src/resolver.ts, a handwritten Pro list in packages/nuxt/src/module.ts, README counts, and the existing public-api manifest. A single generated ownership manifest removes prefix guessing, and because it is versioned and deterministic, Pro can produce the same shape from its own checkout and the two can be merged into a cross-tier map (TASK-OSS-P0-02) without Core ever importing Pro runtime source.</motivation>

<discovery>
  Before writing code, inspect and record:
  1. packages/tooling/src/manifest-generator.ts and packages/core/manifests/public-api.manifest.json — what is already emitted, how symbols are discovered, and whether the output is already deterministic (run `yarn generate:exports:core` twice and diff).
  2. Where Contract Spec v1 metadata lives per component (the `.contract.spec.ts` files and any sidecar/meta exports) and whether it carries a "compound part of X" relationship.
  3. Every current consumer of export inventories: packages/core/src/resolver.ts, packages/nuxt/src/module.ts, apps/storybook, apps/landing registry build (scripts/build-registry.ts), packages/mcp, validators under packages/tooling/src/validators/ (import-boundary.ts, contract-parity.ts, story-status.ts, story-dod.ts, interaction-contract.ts) and packages/tooling/scripts/validate-exports.ts.
  4. Subpath exports declared in packages/core/package.json `exports` and in compat/codemods/nuxt/mcp/testing.
  Write the discovery result into the task handoff; do not start the generator until the authority for each classification is named.
</discovery>

<requirements>
  <schema>
    Add packages/tooling/src/ownership/ownership-manifest.schema.json (JSON Schema 2020-12) and a TypeScript type next to it. Top level: `schemaVersion` (semver string, start at "1.0.0"), `tier` ("core" | "pro"), `sourceCommit`, `generatedFrom` (array of authority file globs), `entries` (array sorted by symbol name). Each entry: `symbol`, `package` (e.g. "@dzup-ui/core"), `subpath` ("." or "./forms" …), `kind` one of `public-component | compound-part | composable | type | recipe | token-module | internal | compat-alias | unclassified`, optional `parentComponent` (required when kind = compound-part), optional `aliasOf` (required when kind = compat-alias), optional `status` (experimental | beta | stable | deprecated, copied from the story status badge when present), `evidence` (array of authority paths that justified the classification).
    Nothing in the schema carries a timestamp; determinism must be provable by `diff`.
  </schema>
  <generator>
    Add packages/tooling/src/ownership/generate-ownership-manifest.ts and a root script `generate:ownership` (and `generate:ownership:core`). Discover symbols from the entry barrels + package.json `exports`, classify from Contract Spec v1 metadata, `.types.ts` type-only exports, compat package membership, and the story status badge. When two authorities disagree or none applies, emit `kind: "unclassified"` with both pieces of evidence and exit 0 — reporting is not failure.
    Write to packages/core/manifests/component-ownership.manifest.json. Sort entries by `symbol` with a stable comparator; serialize with 2-space indent and a trailing newline.
  </generator>
  <validator>
    Add packages/tooling/src/validators/ownership-manifest.ts (root script `validate:ownership`). It regenerates in memory and fails when: the committed file differs from the regenerated one (freshness), any entry violates the schema, a compound-part names a parentComponent that is not a public-component, or a compat-alias points to a symbol that does not exist. It reports the count of `unclassified` entries and fails only if that count is above a checked-in ceiling file (initialised to the current count — ratchet down, never up).
  </validator>
  <non_decisions>Do not change any export, barrel, or manifest ownership to make the generator's job easier. Do not delete or rewrite packages/core/manifests/public-api.manifest.json; the ownership manifest is an additional generated artifact until P0-02 decides whether they merge.</non_decisions>
</requirements>

<example>
{
  "schemaVersion": "1.0.0",
  "tier": "core",
  "sourceCommit": "ae89240…",
  "generatedFrom": ["packages/core/src/index.ts", "packages/core/package.json#exports", "packages/core/src/**/*.contract.spec.ts"],
  "entries": [
    { "symbol": "DzButton", "package": "@dzup-ui/core", "subpath": ".", "kind": "public-component", "status": "stable", "evidence": ["packages/core/src/components/buttons/DzButton.contract.spec.ts"] },
    { "symbol": "DzCardBody", "package": "@dzup-ui/core", "subpath": ".", "kind": "compound-part", "parentComponent": "DzCard", "evidence": ["packages/core/src/components/cards/index.ts"] },
    { "symbol": "DzButtonProps", "package": "@dzup-ui/core", "subpath": ".", "kind": "type", "evidence": ["packages/core/src/components/buttons/DzButton.types.ts"] },
    { "symbol": "useTheme", "package": "@dzup-ui/core", "subpath": ".", "kind": "composable", "evidence": ["packages/core/src/composables/useTheme/index.ts"] },
    { "symbol": "DzLegacyToast", "package": "@dzup-ui/compat", "subpath": ".", "kind": "compat-alias", "aliasOf": "DzToast", "evidence": ["packages/compat/src/index.ts"] },
    { "symbol": "createFooHelper", "package": "@dzup-ui/core", "subpath": ".", "kind": "unclassified", "evidence": ["packages/core/src/index.ts", "no Contract Spec v1 sidecar, not in a .types.ts, exported from root barrel"] }
  ]
}
</example>

<steps>
  1. Complete <discovery>; record the authority for each `kind` in packages/tooling/src/ownership/README.md.
  2. Add the schema, type, generator, and validator; wire `generate:ownership`, `generate:ownership:core`, `validate:ownership` into the root package.json and append `validate:ownership` to `validate:all`.
  3. Run the generator twice; `diff` the outputs to prove determinism.
  4. Add packages/tooling/src/ownership/*.spec.ts covering: stable sort, schema rejection, compound-part parent check, alias target check, unclassified ceiling ratchet, freshness failure.
  5. Commit-free handoff: list the unclassified entries with their evidence so maintainers can decide; do not resolve them yourself.

<validation>

  yarn validate:exports && yarn validate:boundaries && yarn typecheck && yarn lint
  yarn test packages/tooling
</validation>

<success_criteria>Two consecutive generator runs are byte-identical; `validate:ownership` passes on the committed file and fails on a hand-edited one; every Core root/subpath export appears exactly once with a kind and evidence; no export was added, removed, or re-owned; the unclassified list is reported, not silently emptied.</success_criteria>

<stop_conditions>Stop and report when the entry barrels and Contract Spec v1 metadata disagree about whether a symbol is public and no ADR decides it; when classifying requires Core to read Pro source; when the only way to reach zero unclassified is to declare symbols public by implication.</stop_conditions>
```
