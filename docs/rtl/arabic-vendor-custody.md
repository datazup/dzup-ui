> Produced by `TASK-AR-2` of
> [`docs/program-2026-08/oss-recovery-and-shared-kit-tasks.md`](../program-2026-08/oss-recovery-and-shared-kit-tasks.md).

> matrix the RTL work is measured against.

> Evidence date: **2026-08-25**, `ui/dzup-ui` `main` @ `e986952`.

## 1. The headline: nothing Arabic is vendored, because no font is vendored at all

The task anticipated fonts, locale datasets and shaping helpers to inventory.
The inventory is empty, and the reason is worth stating precisely rather than
recording as "none found".

**`git ls-files` returns zero font binaries.** No `.woff`, `.woff2`, `.ttf` or
`.otf` file is tracked anywhere in this repository. The only font files that
exist on disk are Nunito Sans under `apps/storybook/storybook-static/` and
`apps/landing/dist/storybook/` — **Storybook's own build output**
(`sb-common-assets`), untracked, regenerated by every `yarn storybook:build`,
and never shipped in a published tarball (`files: ["dist"]`).

**The library ships font *names*, not font *files*.** Every typography token is
a CSS family stack that resolves against what the user already has:

| Token / recipe | Stack |
|---|---|
| `--dz-font-sans` (default) | `'Inter', ui-sans-serif, system-ui, -apple-system, sans-serif` |
| ThemeRecipe `system` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` |
| ThemeRecipe `geist` | `"Geist", "Inter", ui-sans-serif, system-ui, sans-serif` |
| ThemeRecipe `rounded` | `"SF Pro Rounded", "Nunito", ui-rounded, "Segoe UI", system-ui, sans-serif` |
| ThemeRecipe `serif` | `ui-serif, Georgia, Cambria, "Times New Roman", serif` |
| `--dz-font-mono` | `FONT_FAMILIES.mono` (system mono stack) |

Nothing is `@font-face`-declared, nothing is fetched from a CDN, nothing is
bundled. `grep` for `@font-face`, `fonts.googleapis`, `fonts.gstatic` across
`packages/tokens/src`, `apps/landing` and `apps/storybook` returns no hits.

**So there is no font licence obligation, and there is also no Arabic
typeface.** Those are two halves of one fact — see §4, decision 1.

Nothing in this table is `no` or `owner decision` for **licence** reasons, so

### What `yarn validate:licenses` actually covers

`packages/tooling/src/license-audit.ts` scans *production dependencies of the
core and pro packages* — npm packages, resolved from `package.json`. On
2026-08-25 it reports **9 allowed, 0 blocked, 0 unknown**.

It therefore **does** cover `@internationalized/date`, `lucide-vue-next` and
`reka-ui`, and it **does not and cannot** cover a vendored asset: a font file
committed into `packages/` would have no `package.json` and would pass the audit
silently. That is not a defect today (there are no such assets) but it is the
gap that would open the moment anyone acted on decision 1.

## 3. The RTL verification matrix

The axes below are the ones `TASK-OSS-P4-05` already put in the codebase; this
section names where each check runs so `TASK-OSS-P4-05`'s successors and the
apps have one list to execute against rather than a description to re-derive.

### Axes

| Axis | Values | Declared where |
|---|---|---|
| direction | `ltr`, `rtl` | `DzProvider` `direction`, or `auto` resolved from the locale by `directionForLocale` |
| theme | light, dark | `data-theme` |
| density | default, compact | ThemeRecipe |
| motion | default, `prefers-reduced-motion: reduce` | media query |

The full cross-product is 16 cells per component and **is not** what runs. The
checks below each pick the axes they can actually falsify — a source-level
lint has no theme, and a licence has no density.

### Checks, and where each one runs

| # | Check | Where it runs | Status on 2026-08-25 |
|---|---|---|---|
| 1 | A component declaring `mirrors: 'layout'` uses **no physical `left`/`right` utility** in its variants | `yarn validate:rtl` (source-level, `packages/tooling/src/validators/rtl.ts`) | **enforced.** A deliberate physical case must say `rtl-physical-ok` with a reason |
| 2 | The generated matrix matches the declarations | same validator; `packages/core/docs/rtl-matrix.md` via `yarn generate:rtl-matrix` | **enforced** — the table cannot drift from the anatomies |
| 3 | A rendered component matches its declared RTL contract | `expectRtl` from `@dzup-ui/testing` (jsdom, `yarn test`) | available; used by `packages/core/tests/rtl.spec.ts` |
| 4 | The resolved `margin-inline-start` lands on the correct **physical** edge | `expectRtlComputed` from `@dzup-ui/testing` — **browser lane only**; it throws rather than passing under jsdom | available, **not yet wired into a Playwright project** |
| 5 | Keyboard: ArrowLeft/ArrowRight swap on the inline axis, ArrowUp/ArrowDown do **not** | component keyboard specs; `useTabs` (library) and `BlockCategoryNav.spec.ts` (landing app, TASK-APP-1) | enforced where declared |
| 6 | Icon mirroring: only parts listed in the anatomy's `icons` mirror | `rtl-matrix.md` `icons` column | declared for `DzSelect` (`indicator`); not otherwise asserted |
| 7 | Number formatting uses `Intl` with the active locale — `ar` and `ar-u-nu-latn` render different digits | `packages/core/src/i18n/intl-cache.ts`; `DzProvider` locale specs | locale plumbing enforced; **the `ar-u-nu-latn` numbering-system case is not asserted anywhere** |
| 8 | Text alignment is logical (`text-start`/`text-end`, never `text-left`) | check 1 covers the variants; `DzTable`'s cells were the found defect | enforced in `packages/`, **and now ratcheted in the landing shell** by `apps/landing/src/shellDirection.spec.ts` |
| 9 | A block renders contained and inherits `dir` at every viewport | `yarn test:responsive:landing` — 88 blocks × `ltr`/`rtl` | **enforced**, 88/88 |
| 10 | The app **shell** renders correctly under `dir="rtl"` | nowhere | **cannot run** — see the gap below |
| 11 | Every visible string resolves through the message catalog | `yarn validate:hardcoded-strings` | enforced |

### Coverage today

`packages/core/docs/rtl-matrix.md`: **8 of 144 public components declare an RTL
contract**, because only 8 declare an anatomy at all. The matrix says so in its
own words — *"the rest are silent, not compliant"* — and both rollouts are the
same rollout, ratcheted by `maxWithoutAnatomy`.

### The gap that matters most (check 10)

**No ordinary landing route can render right-to-left.**
`document.documentElement.setAttribute('dir', …)` appears in exactly two files:
`apps/landing/src/pages/BlockPreviewPage.vue` and
`apps/landing/src/templates/previewCustomiser.ts`. The RTL certification reaches
`dir=rtl` only through `/blocks/preview/<id>?dir=rtl`.

So the app certifies RTL for the content it **documents** and never for the
chrome it **is** — which is how 27 non-mirroring declarations and a reversed
arrow key survived in the shell while the library was being made RTL-correct
(`TASK-APP-1`; both now fixed and ratcheted).

## 4. Owner decisions

Ordered by what blocks what.

1. **There is no Arabic typeface, and that is currently unstated.** Every font
   stack ends in `system-ui`/`sans-serif`, and neither `Inter` nor `Geist` nor
   `SF Pro Rounded` carries reliable Arabic coverage — so Arabic text renders in
   whatever the user agent substitutes, with no line-height, no numeral style and
   no weight guarantee from us. Three answers, and the decision is which:
   - **Say so.** Document that Arabic typography is the host's responsibility and
     that `--dz-font-sans` is meant to be overridden. Costs nothing, ships
     nothing, and is honest. *Recommended as the immediate step.*
   - **Name an Arabic family in the stack** (e.g. `"Noto Sans Arabic"`,
     `"IBM Plex Sans Arabic"`, `"Cairo"`). Still vendors nothing and still needs
     no licence — but it only helps users who happen to have it installed.
   - **Vendor one.** This is the only branch with a licence question. SIL OFL
     fonts (Noto, Cairo, Tajawal, Amiri) are shippable **with** obligations —
     attribution, the reserved-font-name rule, and OFL-licensed derivatives — and
     `yarn validate:licenses` **cannot see a vendored file**, so a new gate would
     be needed first. **Do not vendor until that gate exists** (`<licence_gate>`).
2. **Wire `expectRtlComputed` into a Playwright project** (check 4). The helper
   exists and deliberately throws under jsdom rather than passing vacuously, so
   the half of the RTL contract that needs real layout is currently unasserted.
   This is the cheapest real increase in RTL evidence available.
3. **Give the landing app a direction control** (check 10) — a toolbar, a query
   parameter, or a locale — so the responsive certification can cover the shell.
   Until then the shell's RTL correctness rests on a source-level ratchet with no
   rendered proof.
4. **Assert the `ar-u-nu-latn` numbering system** (check 7). `ar` renders
   Eastern Arabic numerals and `ar-u-nu-latn` renders Latin ones; applications
   choose, and nothing currently proves the library honours the choice.

## 5. What was NOT done, and why

- **Nothing was vendored, copied, re-hosted or moved.** `<stop_conditions>`.
- **No deployment-context inventory was regenerated.** The ThemeRecipe ledger
  forbids regenerating the Template and Arabic Language apps' inventories. It did
  not arise: **there is no Arabic Language app in this checkout.**
  `workspace-share/apps/` holds nine apps — `ai-saas-starter-kit`,
  `codeindex-app`, `codev-app`, `nl2sql`, `research-app`, `seo-batch`,
  `template-app`, `testman-app`, `website-app` — and none is it.
- **The Arabic app's vendored core was not evaluated.**
  `DZUP_UI_REKA_DEDUPE_AND_OVERLAY_TESTABILITY_PLAN_2026-08-08.md` records that
  *"Arabic's vendored core is a standalone/deployment fallback"* and that AR-2
  should *"refresh Arabic vendor artifacts only from a canonical built release"*.
  That vendored copy lives in the Arabic app, which is not in this checkout, so
  the artifacts cannot be inspected from here. **This is the one part of AR-2
  that is blocked on custody rather than on a decision.**
- **No proprietary font is bundled.** The `<stop_conditions>` case that says
  "report immediately" does not fire.
