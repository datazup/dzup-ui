# Component Status

A **live** maturity dashboard for every component in `@dzup-ui/core`. Nothing here
is hand-maintained: the rows are built at render time from the real story files —
the `status:*` tag on each `meta`, whether the file ships a `play()` interaction
test, whether its family is a11y-enforced, and whether a Figma `design` link is
wired. When a story changes, this page changes with it.

**{TOTAL_COUNT} components** — {summaryLine}.

**Why this is smaller than the `.vue` file count.** `@dzup-ui/core` ships 205 `.vue`
files, but many are compound sub-parts — `DzCardBody`, `DzAccordionTrigger`,
`DzDialogOverlay` — which have no independent API and are documented **through their
parent**: either on that family's `*Parts` anatomy page, or inside the parent's own
story. **A sub-part without a story of its own is documented, not missing**, and the
matrix below counts parents and anatomy pages rather than individual sub-parts.

`packages/tooling/src/validators/story-status.ts` holds the line: every entry in this
matrix carries exactly one `status:*` tag, so a component can never quietly drop off
the roadmap.

### Entry and exit criteria

The ladder is **experimental → beta → stable**, with **deprecated** reachable from any
tier. A tier that nobody can apply consistently is noise, so each one states what must
be true to enter it and to leave it.

<DocTable
  head={['Status', 'To enter', 'To leave']}
  align={['left', 'left', 'left']}
  rows={ladderRows}
/>

These criteria are **applied by reviewers, not derived by a machine.** What CI enforces
is narrower, and worth stating exactly: `packages/tooling/src/validators/story-status.ts`
asserts that every `Core/<Family>/<Component>` story carries exactly one `status:*` tag
and that a `deprecated` component names its replacement. No check can decide whether a
`stable` component *deserves* to be stable — writing the criteria down makes that
judgment reviewable, which is the most a taxonomy can honestly promise.

## By family

Each family rolls up its component counts by status, plus its a11y gate. **✅ enforced**
means every component in the family passes the WCAG 2.2 AA audit at `error` level
and any regression fails CI; **🔍 audit** means the audit runs report-only while the
family works down its backlog (see
[Accessibility](?path=/docs/guides-accessibility--docs)).

## Full matrix

Every component and its four trust signals. **Tests** = at least one `play()`
interaction test in the story; **A11y** = family gate level; **Design** = a linked
Figma frame via the story's `design` parameter.

**Design reads `—` for every component, and that is correct:** no Figma library
exists for dzup-ui, so nothing is linked. The column stays in place because the
`design` parameter is wired end-to-end and will populate the day a real frame
lands — see [Contributing → Design reference](?path=/docs/guides-contributing--docs#design-reference).
