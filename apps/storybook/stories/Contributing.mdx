# Contributing — Story Authoring

This page is the house style for writing component stories. Stories are both
**docs** and **tests** — treat every story as a recorded state, and add a `play()`
to turn an interactive one into a test.

## Where things live

- **Stories** — `packages/core/stories/{family}/Dz*.stories.ts` (not colocated with
  components — see [CLAUDE.md](https://github.com/datazup/dzup-ui/blob/main/CLAUDE.md)).
- **Shared utilities** — `packages/core/stories/_shared/` (option arrays,
  decorators, `DemoGrid`/`DemoRow`, status taxonomy). Import from `'../_shared'`.
- **Doc blocks** — `apps/storybook/stories/_blocks/` (`StatusBadge`, `DoDont`).
- **Template** — `packages/core/stories/_shared/Dz.stories.template.ts`. Copy it
  to start a new story.

## The shared utilities

```ts
import {
  SIZES, TONES, VARIANTS,        // canonical option arrays (ADR-02)
  sizeArgType, toneArgType, a11yArgTypes, // argTypes fragments
  darkModeDecorator,             // dark-mode preview wrapper (don't inline it)
  DemoRow, DemoGrid, DemoSection,// layout primitives for matrices
  statusTag,                     // status:* tag helper
} from '../_shared'
```

> **Never** re-inline the `data-theme="dark"` wrapper — import `darkModeDecorator`.
> This was deduped across 86 stories in Sprint 0.

## Required stories (Definition of Done)

Every component story must include:

1. **An entry story bound to `args`** — its template uses `v-bind="args"`, so the
   Controls panel actually drives it. Call it `Default` unless a more specific name
   reads better on the page (`DzCalendar` opens with `Month`, `DzSpeedDial` with
   `Fab`). Not applicable to anatomy pages that declare no `args`/`argTypes`.
2. A **gallery/matrix** — `*Gallery` (variant × tone / sizes), laid out with `DemoRow`/`DemoGrid`.
3. **`States`** — disabled / loading / readonly / invalid, **when the component
   declares one of those props**. A component with no state props (`DzVisuallyHidden`)
   needs no `States` story.
4. **A dark-mode preview** — any story carrying `darkModeDecorator`. Conventionally
   `DarkMode`, but the decorator is what matters, not the export name.
5. **`Accessibility`** — focus-ring / ARIA demonstration.
6. At least one **`RealWorld*`** — the component in a realistic composition.
7. ≥1 **`play()`** interaction test where interactive — **await every** `userEvent`/`expect`.
8. **A component description** — a JSDoc block **directly above `const meta`**. It must
   say what the component is for and when to reach for it.

### This is machine-checked

`yarn validate:story-dod` runs the list above against every story and fails CI on the
**enforced** checks. The rest print their counts, so the remaining distance is always
visible:

### Why the description must sit directly above `const meta`

Storybook's `enrichCsfMeta` reads only the Babel `leadingComments` of the `const meta`
statement. Babel attaches a comment to the statement that **follows** it — so a doc
comment separated from `const meta` by fixture data attaches to the fixture, and your
docs page renders no description at all. Intervening `//` comments are fine.

```ts
// ✓ Do — the comment attaches to `meta`, and the docs page renders it.
/** DzTable is a semantic table wrapper. Use DzDataGrid for sorting/pagination. */
const meta = { title: 'Core/Data/DzTable' } satisfies Meta<typeof DzTable>

// ✕ Don't — the comment attaches to `sampleData`. The docs page renders nothing.
/** DzDataGrid is the most complex core data component. */

const sampleData = [/* … */]

const meta = { title: 'Core/Data/DzDataGrid' } satisfies Meta<typeof DzDataGrid>
```

<DoDont>
  <Do>Put the description immediately above `const meta`, below the imports.</Do>
  <Dont>Leave it at the top of the file with fixture data between — it renders nowhere.</Dont>
</DoDont>

## `play()` smoke test

Always `await` interactions so the Interactions panel can log/step them, and so the
a11y audit scans the resulting state:

```ts
import { expect, userEvent, within } from 'storybook/test'

export const Interactive: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement)
    const btn = canvas.getByRole('button', { name: /save/i })
    await userEvent.click(btn)
    await expect(btn).toHaveFocus()
  },
}
```

`_shared/status.ts`; it renders as a badge in the sidebar and (via `StatusBadge`)

## Design reference <a id="design-reference" />

**There is no Figma library for dzup-ui today.** The code is the source of truth: a
component's specification is its `*.variants.ts`, its tokens, and its stories.

`@storybook/addon-designs` is **not installed**. It was, for a while — registered in
`main.ts`, adding an empty *Design* panel to every story and weight to every build,
while not one story carried a `design` parameter to fill it. An addon that renders
nothing is a claim that a design source exists, so it was removed (TASK-FREE-12).

The day a real Figma library lands, re-adding it is a two-line change — add
`@storybook/addon-designs` back to `apps/storybook/package.json` and to the `addons`
array in `.storybook/main.ts` — plus a `design` parameter per component:

```ts
const meta = {
  title: 'Core/Buttons/DzButton',
  component: DzButton,
  parameters: {
    design: { type: 'figma', url: 'https://www.figma.com/design/…?node-id=…' },
  },
  // …
}
```

Two things worth knowing when that day comes: use the frame's deep link (**Copy link
to selection** in Figma, which carries a `node-id`) so the panel opens on the exact
component rather than the whole file, and never point the parameter at a placeholder
— the addon only accepts a real 22-character file key, so a made-up URL renders a
broken iframe.

See [storybook-decisions.md](https://github.com/datazup/dzup-ui/blob/main/docs/storybook-decisions.md)
TASK-0.15 for the original decision and TASK-FREE-12 for its removal.
