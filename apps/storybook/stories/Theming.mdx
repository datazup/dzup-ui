# Theming

dzup-ui ships **light** and **dark** themes out of the box. The active theme is
resolved from a single attribute — `data-theme` — on an ancestor element. No
JavaScript theme context is required for core components; the CSS variables
cascade does the work.

## The `data-theme` switch

```html
<!-- light (default) -->
<html>…</html>

<!-- dark: every descendant re-resolves --dz-* to dark values -->
<html data-theme="dark">…</html>
```

You can scope a theme to any subtree, not just `<html>` — useful for a dark
sidebar inside a light page:

```vue
<template>
  <div data-theme="dark">
    <!-- this region renders dark regardless of the page theme -->
    <DzCard>…</DzCard>
  </div>
</template>
```

In Storybook, the **Theme** toolbar (powered by `@storybook/addon-themes`) toggles
`data-theme` on the preview root. Individual stories can force dark with the shared
`darkModeDecorator` (see [Contributing](?path=/docs/contributing--docs)).

## OKLCH color system

Palette values are authored in **OKLCH** for perceptually-uniform lightness, so a
`-500` step reads as the same visual weight across hues, and dark-mode inversions
stay legible. Raw palette steps are **primitive** tokens
(`--dz-colors-primary-500`); you rarely consume these directly.

## Surface elevation

dzup-ui models depth as a ladder of surface tokens — not ad-hoc shadows. Each tier
pairs with `--dz-surface-foreground` for legible content. In light mode raised
surfaces get brighter; in dark mode they pick up more tint.

## Semantic color tokens

Components reference **semantic** tokens that automatically remap between light and
dark. These are the ones to use in app code. Each intent ships a full state set
(`hover` / `active` / `muted` / `border` …) — see the
**[Color Palette](?path=/docs/guides-color-palette--docs)** page for the complete
reference.

## Do / Don't

✅ **Do** style with semantic tokens (`var(--dz-primary)`), so dark mode is free.
✅ **Do** scope `data-theme` to subtrees when you need a mixed-theme layout.
❌ **Don't** hardcode hex/Tailwind palette colors in component code (ADR-04).
❌ **Don't** read primitive `--dz-colors-*` steps in app code — prefer semantic tokens.
