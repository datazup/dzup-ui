# Feedback <StatusBadge status="stable" />

Feedback components communicate **status, progress, and outcomes** back to the
user. Choosing the right one is mostly a question of _urgency_ and _persistence_:
does the message live inline with content, interrupt transiently, or block the
flow until acknowledged?

## Status-communication taxonomy

| Channel | Persistence | Use it for | Components |
|---------|-------------|------------|-----------|
| **Inline** | Stays in the layout | Contextual status tied to a region or field | `DzAlert`, `DzBadge`, `DzProgress`, `DzSkeleton`, `DzEmpty`, `DzResult` |
| **Transient** | Auto-dismisses | Confirmation of a completed action, undoable events | `DzToast`, `DzNotification` |
| **Loading** | Until data arrives | Pending async work | `DzSpinner`, `DzSkeleton`, `DzProgress`, `DzAsyncBoundary` |
| **Blocking / boundary** | Until resolved | Failures that must be surfaced or recovered | `DzErrorBoundary`, `DzResult` |

## When to use which

> See also [**Guides/Choosing Components**](?path=/docs/guides-choosing-components--docs#toast-vs-alert-vs-notification)
> for the Toast vs Alert vs Notification decision (lifetime × placement).

- **DzAlert vs DzToast** — use **DzAlert** for status that should _stay_ on the
  page (form-level errors, persistent warnings). Use **DzToast** for _transient_
  confirmations ("Saved", "Email moved to trash") that can auto-dismiss and may
  offer a quick **Undo**.
- **DzProgress vs DzSpinner** — reach for **DzProgress** when you know the
  completion ratio (uploads, multi-step jobs); use **DzSpinner** (or
  indeterminate `DzProgress`) when you don't.
- **DzSkeleton vs DzSpinner** — prefer **DzSkeleton** when you can mirror the
  shape of the incoming content (lists, cards, profiles); it reduces layout shift
  and perceived wait. Use a spinner for small, shapeless waits.
- **DzEmpty vs DzResult** — **DzEmpty** is for "there's nothing here yet" inside a
  region; **DzResult** is for the _outcome_ of an operation (often full-page).
- **DzAsyncBoundary vs DzErrorBoundary** — **DzAsyncBoundary** owns the whole
  async lifecycle via `<Suspense>` (loading + error). **DzErrorBoundary** only
  catches synchronous render/lifecycle errors and is composable _inside_ an async
  boundary for finer-grained recovery.

## Accessibility

- **Live announcements** — `DzAlert` uses `role="alert"` for danger/warning tones
  (assertive) and `aria-live="polite"` otherwise; `DzToast`/`DzNotification` rely
  on Reka UI's managed live regions. `DzEmpty` and `DzResult` use `role="status"`
  so dynamic appearance is announced.
- **Progress** — `DzProgress` and `DzTokenProgressBar` expose
  `role="progressbar"` with `aria-valuenow` / `aria-valuemin` / `aria-valuemax`;
  indeterminate progress omits `aria-valuenow` per WAI-ARIA.
- **Busy regions** — wrap async content in a container with `aria-busy` bound to
  the pending state and label the loading region (`role="status"`), as shown in
  the `DzAsyncBoundary` Accessibility story.
- Never rely on color alone — every tone is paired with a title, icon, or text
  label.

## Do / Don't

<DoDont>
  <Do>Use a transient `DzToast` for "it worked" confirmations, with an Undo action where the operation is reversible.</Do>
  <Dont>Use a `DzToast` for errors the user must act on — those belong inline (`DzAlert`) or as a `DzResult`/boundary fallback so they don't vanish.</Dont>
</DoDont>

<DoDont>
  <Do>Show `DzSkeleton` placeholders shaped like the incoming content to minimize layout shift.</Do>
  <Dont>Swap a full layout for a single centered spinner when you can mirror its shape.</Dont>
</DoDont>

<DoDont>
  <Do>Wrap risky subtrees in `DzErrorBoundary` and offer a **Retry** that also clears the failing state before calling `reset()`.</Do>
  <Dont>Call `reset()` without fixing the underlying cause — the child will just throw again immediately.</Dont>
</DoDont>

<DoDont>
  <Do>Pair every tone with text/icon and expose `aria-valuenow` on progress so the state is non-visual too.</Do>
  <Dont>Signal status with color alone (e.g. a red bar with no label).</Dont>
</DoDont>
